Project Title
Campus IT Store & Inventory Management System

1. Project Overview

1.1 Problem Statement

In modern engineering colleges and technical institutions, managing laboratory hardware components (such as Arduino development kits, sensors, and peripherals) and specialized reference textbooks is commonly handled through manual registers or fragmented spreadsheets. This legacy process leads to untracked component depreciation, delayed practical procurement, absence of inventory audit trails, and student delays during lab coursework. To overcome these operational hurdles, this project implements a centralized, web-based Campus IT Store and Inventory Management System. It delivers real-time stock monitoring, automated low-stock threshold alerts, SKU code tracking, and complete CRUD (Create, Read, Update, Delete) lifecycle handling with zero administrative overhead.

1.2 Objectives

  • To design and develop a responsive, full-stack web application adhering to the GeeksforGeeks Express 3-layer MVC architecture.
  • To implement standard RESTful API endpoints (GET, POST, PUT, DELETE) with structured JSON payloads and standard HTTP response status codes.
  • To provide dynamic stock tracking with automated low-stock warnings and one-click item issue/restock actions.
  • To decouple user interface interactions from backend business logic using asynchronous HTTP client communication (fetch API).
  • To verify endpoint robustness through automated CRUD test suites and Postman API collection benchmarks.

3. Implementation and Results

3.1 Implementation Summary

The backend is built using Node.js and Express.js. server.js attaches cors() and express.json() middlewares, routing traffic through routes/itemRoutes.js. The controller itemController.js handles input verification, checks for SKU conflicts (returning HTTP 409), computes inventory states, and sends standardized JSON envelopes. The frontend (public/index.html and api-tester.html) uses asynchronous fetch() requests to deliver seamless single-page updates.

4. Conclusion

The Campus IT Store & Inventory Management System was successfully developed, evaluated, and documented in partial fulfillment of the requirements for the Full Stack Development Mini Project (Web Technology Laboratory - Assignment 9).

By following the established GeeksforGeeks Express 3-layer MVC architecture, the project demonstrates key engineering principles:

  • Complete Separation of Concerns: Routing (routes/itemRoutes.js), controller logic (controllers/itemController.js), and server setup (server.js) are neatly decoupled for scalability and maintainability.
  • RESTful Design Principles: Standard HTTP verbs (GET, POST, PUT, DELETE), stateless communication, and precise HTTP response status codes (200, 201, 400, 404, 409) were verified with 100% test pass rates.
  • Interactive User Experience: Asynchronous client-side rendering (via JavaScript fetch API) eliminated unnecessary page reloads, providing live stock level adjustments and immediate visual feedback.
  • Dual-Engine Reliability: The system automatically operates with live Node.js/MongoDB microservices or transparently falls back to an in-browser simulated engine for zero-friction evaluations.

Future Scope & Enhancements

1. JWT Role-Based Access Control: Introducing authentication tokens to distinguish between Department Faculty/Admin (with edit/delete permissions) and Students (with view-only and requisition permissions).
2. Barcode / QR Code Generation: Generating automated QR codes for every equipment SKU to enable rapid smartphone checkout during lab practical sessions.
3. Automated Reorder Triggering: Integrating email/SMS webhook notifications (via Nodemailer or Twilio) whenever hardware inventory falls below critical threshold limits.
